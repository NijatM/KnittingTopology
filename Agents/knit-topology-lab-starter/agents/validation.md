# Validation

Independently verify algorithms, topology, reproducibility and claim accuracy.

Review against task acceptance and evidence, not the author's desired conclusion. Choose analytic/reference checks and realistic failure cases. Test finite values, dimensional behavior, boundaries, refinement, graph invariants, openings, round-trips and worker cancellation when relevant. Distinguish unexecuted tests from passing tests. Report concrete reproduction steps and severity; avoid cosmetic findings. Do not silently change the code under review. Independent model agreement is not physical validation.

Expected handoff: Actionable findings, actual check results, and explicit verification/validation limits.

Use `templates/result.json` and the relevant project skill. Read `AGENTS.md`, the task and owned inputs first.

# Generation on supplied rectangular OBJ UV charts

Import an OBJ with a complete, single-valued rectangular texture chart and choose its physical source units. The importer retains compatible raw `vt` coordinates and checks the chart before enabling **Generate** and **Draw guide**. A [bent example](../public/examples/bent-rectangle-uv.obj) is supplied in millimeters; the import panel downloads it directly. Meshes without an accepted chart remain available for inspection. STL has no supplied UV chart in this implementation.

## Supported input and numerical screen

Every face corner referencing the same OBJ position index must carry identical parsed UV coordinates. Missing, out-of-range, nonfinite, incompatible or seamed texture coordinates prevent chart use without discarding the support geometry. One- or two-component `vt` records and three-component records with zero third component are supported for UV retention. UV arrays are bounded and checked again on project loading.

The mapping screen requires a connected, consistently oriented manifold disk, one boundary loop, Euler characteristic 1, no isolated vertices and no collapsed, duplicate or geometrically degenerate triangles. Both raw UV axes must have nonzero extent. Their bounding rectangle is normalized independently to [0,1]². Every normalized triangle determinant must exceed 1e-14. Negative or mixed orientation is rejected; no reflection or boundary snapping is performed. The boundary must contain each rectangle corner exactly once, travel along each side monotonically and cover the boundary once. A hole, a cut-off corner or a repeated cover is rejected.

These conditions are informed by Lipman’s global-inversion result for simplicial maps, **Theorem 1**, which combines consistent nondegenerate elements with a bijective boundary. The project checks stored floating-point data at stated thresholds; it does not provide an exact-predicate bijectivity certificate, compute the paper’s optimization, unwrap a mesh or certify the absence of 3D intersections. [Lipman (2014), primary publisher](https://doi.org/10.1137/130939754); [public preprint, Theorem 1 on PDF pages 3 and 10](https://arxiv.org/pdf/1310.0955). Published metadata: _SIAM Journal on Imaging Sciences_ 7(2), 1263–1283, verified against SIAM. The preprint pagination differs from the journal.

## Construction and physical measurements

The project builds coarse connectivity and graph transformations on a unit-square computation chart. For each coarse strip it rounds the mean **physical mapped coarse-edge length / requested spacing**, then uses compatible integer subdivisions. Override counts retain the normal strip rules and workload bounds. Vertex placement is uniform in the computation chart. Raw texture-coordinate units never determine physical size.

Fitting, orientation, influence distance and relaxation operate in normalized UV. Their diagnostics are chart quantities; independent axis normalization changes raw texture angles, and chart distortion changes physical angles and spacing. This is a project heuristic, not an intrinsic surface cross-field solver.

Nodes and ordered cells keep their chart identities through embedding, even when different UV positions coincide in 3D. Barycentric interpolation maps each node to its source triangle. Every graph edge is the image of a straight normalized-UV segment; stored paths insert source-triangle edge crossings and retain the resulting piecewise-linear bends. Reported length is the sum of these world-space segments, subject to floating-point arithmetic and near-collinear crossing thresholds. The stored path convention is `rectangular-uv-edge-crossings-v2`; canonical-path mismatches require regeneration. It is not a shortest geodesic. Support area is the sum of source triangle areas; chord polygon area is reported separately. Per-triangle affine singular scales and their condition ratio describe distortion.

Barycentric interpolation is described in [_Physically Based Rendering_, §6.5 Triangle Meshes](https://www.pbr-book.org/4ed/Shapes/Triangle_Meshes). Closest-point projection uses triangle Voronoi-region tests; see Ericson’s [_Real-Time Collision Detection_, §5.1.5](https://realtimecollisiondetection.net/books/rtcd/toc/). Queries use bounded spatial indices. A closest point on folded or coincident 3D sheets can be ambiguous; picking and stored guide attachments therefore use the actual hit triangle and known UV, and fitting stays in chart space.

## Validity, limits and saving

Mapped validation checks UV cell orientation/Jacobians, rectangle boundary coverage, attachments, canonical edge paths and the existing combinatorial/local geometric invariants. Local 3D chord tests can conservatively reject strongly folded cells. A 90° bent-patch fixture is checked, but arbitrary folded geometry is not guaranteed to generate. No physical, material or manufacturing validity follows from a passing chart screen.

The supported strategy is **Surface patch network**, with the six existing graph families and project coarse presets. The standalone N-sided laboratory remains plane-only. Certain integer-density/operator combinations can fail existing planar checks: the Nested/Ambo case with coarse strip counts [3,1,1,1] is an explicit fail-closed regression. A failure preserves the previous accepted result; it is not replaced by an invalid network.

A mapped edge is limited to 1024 stored path samples, with at most two million samples across final and coarse graphs. Coarse edges use the same per-edge bound. Very fine support triangulations may exceed these limits even at coarse network density; simplify the support first. The normal base-cell, subdivision, import and project-size bounds also apply.

Project JSON retains raw UVs, the mapping convention, graph identities/paths and guide triangle attachments. Chart and graph checks, including any supplied coarse complex and ordered patch corners, are repeated on load; a saved mapping flag is not a certificate. Shared immutable geometry supports cached content fingerprints for freshness, while worker clones produce the same signature. History accounts for both the support mesh and generated graphs. Original analytic projects and inspection-only imported projects remain readable. Method records and BibTeX exports select the mapping reference only for this mapped mode.

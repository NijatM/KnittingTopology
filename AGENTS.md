# Knitting Topology — operating rules

Read `project-brief.json`, `docs/data-contract.md`, and the assigned task first.

- The user authorizes continuous local implementation and verification without milestone pauses. **No Git actions at all**: no init, status, branches, worktrees, commits, pushes, or deployment. The user will initialize and publish later.
- One coordinator owns integration and task state. Extra workers are authorized when useful; use genuinely disjoint owned paths and settle interfaces before parallel implementation. Never overwrite another worker's changes. Do not start recursive agent loops.
- Use GPT-6.1 Sol for bounded implementation tasks and Claude Opus 5.5 through the user's authenticated Claude Code subscription for scientific review. Record actual provider/model and checks; never claim a call happened if it did not. No separately billed API automation, credentials in source, or client-side AI dependencies.
- Preserve the original starter under `Agents/`. Its recommendations yield to the user's settled decisions and these rules. Do not activate worktree-based profiles.
- Keep the numerical core independent of React, the DOM, and Three.js. Use meters internally and millimeters in controls. Preserve stable IDs, ordered cell boundaries, explicit graph connectivity, surface revisions, and provenance.
- Separate geometry, coarse topology, density/subdivision, pattern transformations, and surface embedding. A decorative network is not a stitch graph or structural analysis. No manufacturing or textile capacity claims.
- The first generator includes a documented pattern-based quadrangulation subset. Cite Takayama et al. (2014) and Oval et al. (2018); state implemented subsets and extensions honestly. Do not claim full paper reproduction or uniform spacing guarantees without checks.
- Shared cube seams are shared graph identities, not disconnected coincident lines. Preserve sharp edges. Sphere seams and extraordinary vertices are explicit. Keep geometric crossings distinct from intentional adjacency.
- Check actual invariants, analytic cases, invalid inputs, dimensions, transformation behavior, refinement where relevant, worker cancellation/stale results, undo, and project round-trips. Model agreement is not validation.
- Expensive generation uses cancellable workers. Keep the old result visible until an accepted replacement, reject superseded inputs, report numerical failures, and never install an invalid result silently.
- Use primary references. Record tolerances, units, algorithm versions, supported inputs, and evidence limits. No invented measurements, material constants, citations, or tests.
- Website style follows `../KnittingPixelArtEditor`: dark monochrome, IBM Plex Mono, square bordered controls, left workflow, central viewer, right inspector. Accessible interactions and a responsive layout are required.
- Workers report changed paths, actual checks, skipped checks, and remaining limits. At most two repair attempts before a concrete distinguishing check or coordinator decision. Prefer useful artifacts over orchestration infrastructure.
